    feat: Implement Kademlia DHT Enhancements and BitSwap Integration
    
    This update introduces a significant set of features and improvements to the Kademlia DHT implementation and integrates a foundational version of the BitSwap protocol.
    
    Key changes include:
    
    1.  **Limited Subnet Awareness**:
        *   `SubnetRoute` now includes a `subnetId` to tag routes.
        *   `RoutingTable.getNearestNodes()` allows filtering by `subnetId`.
    
    2.  **S/Kademlia Security Extensions**:
        *   Node IDs (`NUID`) are now generated from the SHA-256 hash of an agent's public key via a new factory in `NUID.kt`.
        *   Agents (`WorldAgent`) now manage a `KeyPair` (using a `DummyCryptoService` for now).
        *   A `SecureMessage<KademliaPayload>` wrapper adds sender's public key, a signature (over `hash(payload + timestamp)`), and a timestamp to all Kademlia messages for integrity, authenticity, and basic replay resistance.
        *   `SecureKademliaCodec` handles the serialization (to JSON), signing, and verification of these secure messages.
        *   Defined `KademliaPayload` sealed interface and basic message types (`PingRequest`, `FindNodeRequest`, etc.).
        *   I've also included unit tests for `SecureKademliaCodec`.
    
    3.  **BitSwap Protocol Integration**:
        *   Defined BitSwap message structures (`BitswapMessage`, `Wantlist`, `BlockContainer`, etc.) based on IPFS specs (v1.2.0) and made them serializable.
        *   Implemented core BitSwap components:
            *   `CID`: A simplified Content Identifier class.
            *   `BlockStore`: Interface and `InMemoryBlockStore` for block storage.
            *   `WantManager`: Manages local node's wantlist and tracks active wants.
            *   `PeerLedger`: Tracks per-peer BitSwap state (what they want, exchange balance).
            *   `BitswapEngine`: Orchestrates BitSwap logic, handles messages, and interacts with other components.
        *   Integration with Kademlia `WorldAgent`:
            *   BitSwap messages are transported within a `BitswapEnvelope` (a type of `KademliaPayload`) over the secure Kademlia channel.
            *   `WorldAgent` instantiates and manages `BitswapEngine`.
            *   Kademlia `findNode` is used for peer discovery; discovered peers are fed to `BitswapEngine` to proactively share wantlists.
        *   I've included unit tests for `WantManager`, `PeerLedger`, and `BitswapEngine` (using fakes).
    
    4.  **Adaptive Control for Dynamic Topologies (in Kademlia `RoutingManager`)**:
        *   `RoutingManager` now features adaptive k-bucket refresh intervals, adjusting based on the observed rate of node evictions within a defined window.
        *   Logic for targeted peer discovery for sparse k-buckets is implemented (generates an ideal NUID for the bucket range, though the actual `findNode` call is currently simplified).
        *   I've included unit tests for these adaptive behaviors in `RoutingManager`.
    
    5.  **Routing Table Management (`RoutingManager`)**:
        *   Enhanced `RoutingManager` handles k-bucket refreshing, pings, and eviction of unresponsive nodes.
        *   Includes strategies for handling full k-buckets.
        *   Unit tests for `RoutingManager` were added earlier.
    
    6.  **General**:
        *   Introduced `DummyNetworkService` and `DummyCryptoService` to allow higher-level logic to function and be tested in the absence of real network or cryptographic implementations.
        *   Added various configuration options to `KademliaConfig`.
        *   I've put in extensive unit testing for newly added, complex components.
    
    This work significantly advances the capabilities of the DHT, laying groundwork for secure and efficient operation in a P2P network, and enabling block exchange via BitSwap. I've noted areas for future work include implementing a standard Kademlia distance metric, full provider record system, and concrete network/crypto services.
